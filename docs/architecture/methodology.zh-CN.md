# 方法论与技术架构

## 设计目标

系统用于生成可审计的历史领土重建假说，同时严格区分历史证据、模型假设、求解器行为和地图表达。

生成的多边形不需要伪造一条“一对一来源引用”，但影响它的来源观察、审查后的锚点、摩擦输入、转换规则、运行设置和未解决问题必须能够追溯。

## Agent 研究链

预期操作者是研究型 Agent。它需要检索目录与合法资料库，取得可按页定位的材料，记录访问和权利状态，比较不同记载，再决定每项主张可以承担什么角色。来源发生冲突时，Agent 必须缩小主张、降级、移除，或把它保存在独立争议情景中。求解器默认值不能代替历史分歧的处理。

仓库提供这套工作的协议和可执行约束，不包含自治网页浏览运行时。资料发现由 Agent 当时可用的工具完成，结果以观察、决策和访问记录写入案例。年代、翻译或政治解释无法通过现有材料解决时，仍需人工审查。

Agent 的操作顺序可以概括为：**证据检索 → 结构化主张 → 编译空间假说 → 诊断不确定性 → 定向搜索下一批证据**。每一步都产生可复核对象；当前空间假说会改变下一轮研究行动，流程不会停在出图。

## 认识论边界

本方法把传统制图流程中容易混在一起的五层陈述拆开：

1. 某个来源包含一项记载；
2. 这项记载支持一条历史主张；
3. 该主张可以承担某种空间建模角色；
4. 模型生成一个领土表面；
5. 这个表面以边界假说的形式展示。

某一层成立，不会自动授权下一层。战场位置可以有充分史料支持，同时仍被拒绝作为领土种子；现代河流中心线可以非常准确，同时缺乏充当历史边界的证据。

## Prospective held-out 案例

Prospective 案例具有独立于重建的生命周期：`preregistered → evidence_collection`，随后进入 `reconstructed_pre_evaluation → evaluation_opened`，或者进入终态 `completed_no_reconstruction`。评估开始前，held-out 历史地图只存在于 metadata-only 登记表，不能进入 source、observation、claim、model decision、scenario 或空间输入。第一个 Git commit 冻结预注册；首次打开地图主体前，第二个 commit 必须冻结证据、模型设置、输出、固定比较单元与哈希。负结果进入终态后永远不会打开 held-out 材料。

仓库验证会拒绝研究材料中的 held-out 标识、封存案例内的地图主体文件与提前生成的边界输出，以及不符合冻结材料清单的哈希。这能建立材料隔离和可核查声明，不能证明完整的人类浏览历史。因此任何意外 snippet 或 preview 暴露都必须披露，并排除或标记受影响候选。

## 明确 era 的 BCE 时间契约

BCE prospective 案例不使用负 ISO 日期。记录必须保存 calendar 标签、`era=BCE`、正整数 `year_bce`、证据时间分辨率、时段定义、年代不确定性和显式的天文纪年转换。公元前 `n` 年按 `astronomical_year = 1 - n` 转换；因此公元前 701 年对应天文纪年 `-700`，公元前 1 年对应天文纪年 `0`。

`campaign_horizon` 是证据分辨率，不是日历瞬间。它可以把通常归属于同一次远征的行动及其直接处置放入同一研究时段，同时保留行动顺序、同步关系和文本成书的不确定性。Validator 会核验转换结果并拒绝负 ISO 形式的替代写法。即使空间或数值后端需要天文纪年，公开研究记录仍保留历史 era/year 表达。

## Append-only prospective 证据轮次

Prospective 预注册完成后，冻结内容必须保持逐字节不变。后续研究以 source、observation、claim、decision、gap 和预算增量写入 `research/rounds/<round-id>/`。`lifecycle.json`把冻结清单与预注册 commit 绑定到已审核的轮次清单；当前状态由基线加这些增量计算，不通过重写基线 bundle 取得。

Validator 会重算每个轮次文件哈希，检查前序状态链与精确文件集合，拒绝重复的认知对象 ID，核验跨记录引用与来源访问字段，统计查询、记录检查、采纳数量和每 gap follow-up，强制合法阶段迁移，并扫描全部轮次材料中的 held-out 标识符。重建 gate 失败后进入终态 `completed_no_reconstruction`，后续轮次与 polygon 输出都被禁止。哈希链在仓库内提供篡改可见性，Git 历史提供持久不可变性。

已经完成的 Mercia–Welsh 案例实际执行了严格预注册的负结果路径。780—796 年地点级政治控制证据未达到重建 gate，预算控制与停止规则因此在不生成几何的条件下终止案例，held-out atlas 永久保持封存。该终局证明协议在证据不足时成功执行；它不表示项目失败，也不构成历史准确率结果。

## 端到端工作流

```text
来源
  -> 观察
  -> 证据主张
  -> 经审查的模型决策
  -> 后端中立的重建请求
  -> 空间后端输入
  -> 重建运行
  -> 输出要素
  -> 不确定性诊断
  -> 排序后的证据搜索目标
```

默认命令链为：

```text
validate -> compile-request -> reconstruct/run -> research-loop
```

`validate`、`compile-request`、`reconstruct` 与 `run` 会先编译 v0.2 认知状态，再跨越 XTENT 后端边界。哈希冻结的 v0.1 adapter 只通过明确的 `legacy-*` 命令服务回归 fixture。`historical-geo figures` 保留基线和消融图件检查。

## 核心数据模型

| 对象 | 含义 |
|---|---|
| Source | 可引用的文本、数据集、地图、地名库或合成 fixture。 |
| Observation | 从来源直接读取的陈述、事件、测量或位置。 |
| Evidence claim | 带实体、时间、空间含义、状态和观察引用的历史解释。 |
| Model decision | 把证据或明确声明的假设转换为后端中立的有界模型指令。 |
| Spatial anchor | 经过审查并允许进入分配的地点点位。 |
| Historical phase | 某实体在定义时间段内的建模状态。 |
| Reconstruction run | 有效输入、校准版本、处理元数据和哈希。 |
| Boundary hypothesis | 带谱系和局限说明的模型生成几何。 |
| Research gap | 带研究问题、资料策略、成功标准和停止条件的未解决事项。 |
| Search target | 因证据情景改变当前空间假说而被提升到下一研究轮次的开放缺口。 |

v0.2 JSON 契约位于 `schemas/`。除 JSON Schema 结构验证外，`historical_geo.research_contracts` 还执行引用和语义检查。

## 编译器与后端边界

研究编译器把经审查的决策转换为确定性重建请求，研究层无需使用 XTENT 词汇。通用角色包括：

- 控制点；
- 空间约束；
- 通行约束；
- 明确排除项；
- 仅用于展示的上下文。

每个情景都带有显式控制点 allowlist；空列表表示不选择任何控制点，不会回退为全部 admitted 点。已纳入的空间或通行假设继续生效，除非情景明确排除。

XTENT 后端把其中受支持的角色翻译为种子、阶段和摩擦要素。其他空间推断后端可以通过自己的翻译器消费同一份认知状态。

公开契约使用有界等级代替无限制调参。阶段影响范围由具名 projection class 表达；自然多边形成本使用 `hard`、`soft` 或 `porous`。这些等级对应的数值属于模型校准，不属于历史证据。

遇到以下情况时，编译器和后端会在重建前失败：

- 证据或来源引用不存在；
- 非面状关系未经授权进入分配；
- 种子坐标未知；
- 展示记录泄漏到分配层；
- 自然要素角色未经允许；
- 本应使用有界等级的位置出现原始调参值。

## 不确定性诊断与搜索策略

证据情景和模型情景在统一分配格网上与 reviewed baseline 比较，发生变化的格网单元会追溯到各情景改变的决策。诊断按切片报告 `evidence_gap`、`model_sensitivity` 或 `mixed`，格网数量不解释为概率。

开放证据缺口只有在与它关联的证据情景确实改变空间分配时，才会成为搜索目标。目标按受影响格网数和显式决策关联排序，并保存研究问题、优先资料类型、成功标准与停止条件。纯模型敏感性只形成模型诊断，不能自动生成文献搜索任务。

## 重建引擎

### 投影栅格

Fixture 几何和地点点位以 WGS84 保存。栅格化前，陆地、自然要素和种子会转换到配置的 Lambert conformal conic 投影。公开案例使用 10 km 工作栅格。

近似海岸种子若落入水体栅格，可在三格以内确定性移动到最近陆地格。不同实体种子落入同一格时，流程会明确失败。

### 成本距离分配

XTENT 核心先建立摩擦表面，再从经过审查的锚点计算最小成本影响。只有影响值为正的格网进入分配。带 `point_control` 主张的锚点会保留其所在格，即使相邻更强的影响场原本会将它消除；该规则只保留点观察，不会人为扩大周边范围。

### 几何生成与拓扑

分配后的格网转换为实体表面，并按陆地掩膜裁剪，随后检查有效性和排他覆盖。非线性重投影可能在 WGS84 中产生微小共享边重叠，因此流程按确定性实体顺序恢复排他覆盖；有效性、无重叠或实体保留任一失败，运行即失败。

## 自然要素实验

现代几何只提供位置，不赋予历史意义。自然要素只有在存在经过审查的历史角色，或被明确标为模型假设时，才能影响分配。

公开案例使用：

- 黎巴嫩山：`soft` 多边形成本，模型假设；
- 托罗斯山脉：`porous` 多边形成本，模型假设；
- 约旦河：仅作为展示上下文。

`flat` 场景会移除两项山地成本决策。基线与 flat 场景的对称差使用等面积 `ESRI:102025` 计算，只表示模型敏感性，不是准确率。

## 受保护的边界对齐

`historical_geo.attractors.align_shared_boundary` 用候选向量评估一条共享边，不会分别吸附两个实体多边形。候选必须通过全部约束：

- 距离接近；
- 方向相似；
- 最大位移；
- 面积变化限制；
- 实体保留；
- 几何有效；
- 无重叠；
- 覆盖保持。

公开诊断包含一条通过检查的近似平行合成候选，以及一条方向检查失败的真实约旦河候选（相似度 `0.0209`，要求 `0.8`）。候选被拒绝后，原始几何保持不变。

## 验证与谱系

验证范围包括：

- JSON 结构和标识符引用；
- 证据资格与假设标签；
- 预期实体保留；
- 几何有效和无重叠；
- 陆地掩膜约束；
- 有效输入与输出哈希；
- 边界吸引器诊断；
- 图件非空和语义 QA；
- fixture 许可证与来源检查。

每次公开运行都会写出有效求解器输入和运行 manifest。研究缺口继续保持可见，不会被转化为任意几何。

## 实现模块

| 模块 | 职责 |
|---|---|
| `research_contracts.py` | v0.2 认知状态、诊断和搜索目标验证 |
| `compiler.py` | 从审查决策生成后端中立重建请求 |
| `backends/xtent_backend.py` | 从通用请求生成确定性 XTENT 输入 |
| `diagnosis.py` | 情景归因与下一轮搜索排序 |
| `research_case.py` | 案例级编译、运行和研究闭环编排 |
| `contracts.py` / `adapter.py` | 冻结的 v0.1 兼容与回归基线 |
| `xtent.py` | 成本距离影响与分配 |
| `pipeline.py` | 投影、摩擦、矢量化、谱系、哈希与 QA |
| `attractors.py` | 受保护的共享边对齐 |
| `render.py` / `figures.py` | 静态输出、诊断与图件 QA |

XTENT 分配核心从早期 compiler 实验中恢复。公开谱系、Adapter、编排、边界吸引器、渲染和 fixture 均依据当前公开契约编写；旧式路径、私有数据和旧生产驱动脚本没有进入当前项目。

## 主动限制

- 不包含完整扫描地图提取管线。
- 不自动把每一种历史关系转换为面。
- 不宣称河流或山地天然构成政治障碍。
- 不使用影响过模型构建的参考地图进行历史准确率评测。
- 不对两个案例切片之间的连续变化建模。
